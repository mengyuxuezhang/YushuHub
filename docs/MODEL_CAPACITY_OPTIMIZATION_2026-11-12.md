# 模型并发优化与隔离验收

日期：2026-11-12。基于 YushuHub master `78df029` / 1.9.70，在 `perf/model-600-isolated-20261112` 本地分支实施。未合并、部署或发布新版本。

原始问题与环境见 [600 路基线报告](MODEL_CAPACITY_600_2026-11-12.md)。本次仅使用独立 loopback 应用、临时 MySQL 容器、虚构用户和模拟上游，没有访问线上数据库或付费模型。测试服务和容器已停止，测试数据保留用于复核。

## 已实现

### 会员补建并发安全

- 补建事务使用单次 `READ COMMITTED`，不修改连接池会话默认隔离级别。
- 锁住用户主键后检查/补建会员，去掉共享免费会员卡的 `FOR UPDATE`，避免与会员索引间隙锁形成原来的锁循环。
- 已正确初始化的免费会员卡不再逐次无条件 UPSERT；仍会修复不符合约定的旧卡配置。
- 只对明确的数据库死锁/锁等待超时做最多两次事务重试；先回滚、释放连接，再短暂退避。未知错误及不确定的提交结果不会自动重放。
- 重试耗尽返回受控的 `503 / DATABASE_BUSY`，文本模型入口不再把原始死锁 SQL 当作用户输入错误。
- 补建仍不重复发放注册积分，会员、余额和消费流水合同保持。

### 请求准备与 Key 使用

- 会话查询在同一 HTTP 请求内共用一次读取；新 HTTP 请求仍重新验证，不缓存已撤销会话。
- 文本调用复用已认证用户上下文，避免路由与解析器多次读取同一用户；按组织、分类、目标模型 ID 缩小模型查询，保留原模型 ID 严格大小写语义与默认模型顺序。
- 模型解析从启动大文件移入 `src/services/model-proxy-context.mjs`。
- 只有一个可用 Key 时，将 `last_used_at` 写入合并到每秒一次，最多保留 2048 个进程内条目；多 Key 仍逐次更新以保持轮换行为。每次选择都重新查询可用状态和模型范围，不缓存明文 Key 或授权结果。
- `success_count`、消费流水和余额仍逐次可靠写入，没有用可能丢数据的异步计数替代。
- 数据库池默认保持 10，新增受限的可配置入口，没有根据单轮实验盲目增大连接数。

### 流式背压和退出路径

- 独立服务处理 SSE 转发；写入返回 false 后等待 drain，停止继续读取上游。
- 监听客户端断开、响应错误、超时和取消，清理临时监听器并取消 reader。慢客户端耗尽等待期限时断开下游，不误罚模型 Key。
- 增加流空闲与总时长限制，区别于既有响应头超时。
- usage 元数据观察缓冲限制为 1MiB；超大单行仍原样转发，只跳过该行元数据解析，防止无换行输出无限增长。正常尾部 usage 和拆分 UTF-8 均可识别。
- 原样转发供应商字节与来源证明字段，不向签名流注入自行构造的成功/错误帧。响应头已发送后的异常不能再变更 HTTP 状态，而是终止未完整的流；不会补发 `[DONE]` 假装成功。

### 入口容量保护

- 文本聊天 JSON 解析前检查全进程请求数和原始请求体总预算，超限快速返回 429，不建立无界等待队列。
- 未知长度或压缩请求按 20MiB 解压上限预占预算。普通请求仍保留原有单次 20MB 上限。
- 认证后再限制每用户并发，模型解析后限制每供应商并发；结束/失败路径释放计数。保护拒绝发生在上游调用前，不扣积分、不记录 Key 失败。
- 正确覆盖 Express 大小写及尾斜杠别名，防止绕过入口预算。
- 显式提供可调监听 backlog，默认 2048，用于改善瞬时建连接纳；它仍受操作系统及前置代理限制，不是连接数保证。

## 复测结果

以下为单次本地观测；模拟发帧、Windows/Docker 开销与共享主机噪声影响延迟，不作为生产 SLA。

| 场景 | 优化前 | 优化后 | 验收 |
| --- | --- | --- | --- |
| 600 路高频流，50 路/100ms，30 秒/600 帧/256 字符 | 首字节 P95 8.12 秒 | 6.48 秒 | 600 成功、峰值 600；同参数探索对照约改善 20% |
| 600 路基础持续流，目标 60 秒 | 首字节 P95 5.70 秒 | 2.88 秒 | 600 成功、峰值 600；前轮瞬时/后轮分批建连，非严格 A/B |
| 600 个缺会员账号首次并发补建 | 基线 600 路阶段有 450 次死锁失败（前轮已有部分用户补建） | 600/600 成功 | 再重复一轮仍全成功；每人只有一条有效会员 |
| 600 个已过期会员，瞬时建连 | 基线未单测 | 600/600 成功，峰值 600 | 无连接拒绝/未处理死锁；每人一条有效会员 |
| 600 次慢读取请求 | 写缓冲峰值约 289KiB | 64KiB | 600 次完成；本轮上游重叠峰值 550，不冒称 600 路慢读同时活跃 |
| 单用户瞬时发起 600 次 | 全部放入数据库/上游 | 8 次成功、592 次明确 429 | 只扣 8 次积分，Key 失败计数未因保护拒绝增加 |
| 600 个约 256KiB 请求体 | 有本机 TCP 建连失败 | 511 次完成、89 次内存预算 429 | 只扣成功次数；保护拒绝不是未知错误或漏结算 |

高频流独立复测：600 个不同请求 ID、600 条消费流水、消费 600 积分、Key 成功计数增加 600；用户余额总计从 6,000,000 降到 5,999,400。应用 RSS 峰值约 256MiB，和基线约 254MiB 接近，没有宣称所有场景内存都下降。

原本的缺会员场景连续两轮共产生 1200 条唯一消费流水、扣除 1200 积分；仍只有 600 条有效会员，每用户最多一条。过期会员复测也核对了相同不变量。积分未因会员修复额外发放。

同组高频流观察到会话读取从 1200 次降为 600 次，普通用户查询从基线窗口的 2339 次降为 600 次。优化后完整结算窗口共 8409 次 SQL；基线统计在部分 Key 收尾前结束，不使用它计算精确的每请求 SQL 降幅。数据库排队仍存在，剩余工作需要在生产等规格 Linux 环境测量。

大输入场景 RSS 峰值约 585MiB；该轮成功接纳的请求数也比基线更多，不能把它解释为内存优化失败或声称已获得进程内存硬上限。请求体预算约束的是原始输入字节，JSON 对象、转发副本和 GC 保留均会额外耗内存。

## 配置

环境变量修改后重启对应管理端实例生效；默认值适用于本次实现，并不代表任意服务器承载能力。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `AI_DB_CONNECTION_LIMIT` | 10 | 数据库池，允许 1–128，非法值回退默认 |
| `AI_ADMIN_LISTEN_BACKLOG` | 2048 | TCP 接纳 backlog 提示，上限 65535 |
| `AI_MODEL_MAX_CONCURRENT` | 640 | 当前进程聊天 HTTP 请求上限 |
| `AI_MODEL_MAX_PER_USER` | 8 | 单用户在处理中的文本请求上限 |
| `AI_MODEL_MAX_PER_PROVIDER` | 640 | 单供应商文本请求上限，包含结算阶段 |
| `AI_MODEL_MAX_BODY_BYTES_IN_FLIGHT` | 134217728 | 128MiB 原始 JSON 预算，非进程 RSS 硬上限 |
| `AI_MODEL_STREAM_IDLE_TIMEOUT_MS` | 180000 | 收到响应头后无流进展的期限 |
| `AI_MODEL_MAX_DURATION_MS` | 900000 | 上游代理最大时长，默认 15 分钟 |

容量上限是**每进程**而非分布式总额。多实例部署需要按数据库/上游总额度分配，不能直接启用多进程后认为配额仍是全局唯一。每用户请求超过 8 时会出现新保护行为，需要更多合法并行的业务应显式配置并复测。

新增保护只覆盖 `/api/client/model/v1/chat/completions`；不把本轮文本压力结论扩展到图片、音频和模型任务接口。

## 本地证据

原始 JSON 位于被忽略的 `capacity-results/`：

- `results-optimized-warm.json`：正常、持续、慢读、大输入和单用户保护。
- `results-optimized-cold.json`：缺会员账号连续两轮。
- `results-optimized-expired.json`：已过期会员与瞬时建连。
- `results-optimized-rate.json`：与基线参数匹配的高频流。

复现命令沿用基线报告的脚本，增加 `CAPACITY_COLD=1`、`CAPACITY_EXPIRED=1` 或 `CAPACITY_REPEAT=2` 选择相关场景。切换场景应清除不适用的变量；不要复制整个结果目录到公开仓库或供应商包。
