# 管理后台 1.9.69 与部署工具 1.3.0

修复系统更新和独立部署工具在重启验证时仅比较 PM2 PID 的问题。监听进程可以是该 PM2 实例本身，也可以是同一应用目录中的子孙进程；通过 npm 启动不再仅因 PID 不同而失败。保留真实端口冲突、权限不足和多实例歧义的拦截，并记录具体诊断信息。

部署工具 1.3.0 新增“预览修复方案”和“执行修复”，支持重装当前版本依赖、按现有配置修正 PM2 端口、重启或重建记录，以及使用同版本 ZIP 恢复程序文件。配置、经营数据、上传文件和更新产物继续保留；修复不静默改变版本。

独立工具的升级、修复及回滚保存操作前的准确代码快照，失败后恢复并验证原版本。系统内更新补充安装阶段失败恢复、跨入口并发锁及重启验证进程的锁交接。诊断导出包含真实运行版本、配置版本、PM2 名称、端口归属和重启状态。

旧后台可通过系统更新获取 1.9.69；已有启动异常或文件损坏的实例可关闭旧工具后重新执行服务器安装命令，使用工具 1.3.0 的修复入口。需要补程序文件时必须选择该实例当前版本的 ZIP。详见 [升级与修复说明](ADMIN_UPDATE_REPAIR.md)。
