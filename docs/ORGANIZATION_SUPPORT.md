# 一级协助直属二级的权限与审计

此能力仍在开发验收；当前开发分支新增入口，不自动改变任何既有套餐、岗位或正式部署。

中心可在新套餐版本中单独授予一级`organizations.children.details`及`organizations.children.support`。三个基础模板均不默认授予，二级套餐禁止包含这两项。岗位同时需要相应权限；启停还须`end_users.manage`。中心套餐变更仍经影响预览和显式发布，不能在一级本地追加中心能力。

首版协助范围为分页查看直属二级终端账号的用户名、显示名、状态、积分余额及创建时间，以及启停终端账号。不进入二级身份，不代改密码、资金、会员、支付、模型、供应商配置或授权。其他组织经营数据仍保持原隔离。

每次操作强制在线刷新授权，网络宽限不能用于协助。服务端从原登录会话取得操作者与一级组织，重新核对中心一二级绑定、实例、授权版本及本地直属关系/经营状态。请求中的组织、员工或经营所有者字段不能改变归属。目标二级须具有终端管理能力。

明细查询使用`POST /api/organization-support/:id/end-users/query`，请求含8至500字原因、分页及可选搜索。每页至多50条，在同一事务写入审计后才返回明细；不返回密码、Token、连接或终端设备信息。查询审计只保存搜索摘要、页码、数量与原因。

启停使用`POST /api/organization-support/:id/end-users/:userId/status`，请求含`status`、`expectedStatus`、原因和唯一`commandId`。变更、原会话删除和审计在同一事务完成；重试不重复变更或追加审计，同编号不同内容拒绝。旧指令重放返回原结果及当前状态，不能覆盖后来操作。启用不会恢复已撤销会话。

审计保留实际操作者、一级组织、目标二级、终端账号、中心授权版本、原因及变更前后状态。一级可通过既有组织审计查看直属二级记录，二级仍只查自身记录。此机制不改变一级服务器实际持有数据库的源码部署边界。
