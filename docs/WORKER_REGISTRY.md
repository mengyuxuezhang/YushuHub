# 构建机身份登记与调度

构建机鉴权、心跳接收、排队领取和中心列表共同使用服务端受控身份登记。新增节点不需要修改源码中的机器名称。

## 配置

官方构建服务通过`AI_WORKER_IDENTITIES_FILE`读取运营方维护的JSON文件：

```json
{
  "version": 1,
  "workers": {
    "example-worker": "<对应Token的64位SHA-256十六进制摘要>"
  }
}
```

示例中的摘要须替换，不能直接运行。Token随机生成，原值仅放在对应构建机的受控凭据存储中；服务端保存摘要。文件不能放进公开静态目录，部署账号只读，运营方负责写入。每个Token只对应一个合法节点ID，最多100个节点、64KiB配置。

中心在每次鉴权及调度/列表查询时重新读取登记，不缓存已撤销节点。文件缺失、损坏、超限或条目格式无效时拒绝，不回落到旧凭据或默认机器。重复摘要对应的身份不能鉴权或参与调度。请求体和`X-Worker-Id`必须与Token绑定身份一致，客户端不能自行登记节点。

兼容模式仍支持`AI_WORKER_TOKEN`加显式`AI_WORKER_LEGACY_IDS`，调度使用同一显式ID范围；设置身份文件后兼容模式不再兜底。没有显式身份范围时保留原默认列表，实际鉴权仍须满足已有凭据规则。

`AI_WORKER_PRIORITY`只对已登记节点排序，不授予身份。版本匹配、最近心跳、忙闲状态、停用名单和任务领取的数据库竞争检查保持有效。

## 下游展示

下游从已鉴权的官方构建中心取得节点列表，不使用自己本地的构建机登记再次过滤。中心负责排除已撤销节点；下游校验ID、去重并限制列表大小。显示一个远程节点不会授予它本地领取任务或上传的权限。

## 凭据及节点变更

1. 在受控环境创建节点专用Token及上传身份，登记摘要；上传账号只能访问自己的暂存范围。
2. 按节点实际Windows账号保护Token，使用独立源码、缓存、工作目录和固定上传主机密钥。
3. 核验真实进程账号、中心心跳、版本、领取及产物后启用。拒绝未知ID、错误Token、身份冒用和越界上传。
4. 退出使用时先处理正在执行的任务，再撤销登记和上传身份；不得通过删除登记清除已累计受理的构建次数。

检查：`npm run check`包含鉴权和调度回归；真实验收还须验证HTTPS、数据库受理次数、上传权限及产物，不能以单元测试替代。
