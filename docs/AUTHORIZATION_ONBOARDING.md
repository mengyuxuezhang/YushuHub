# 统一授权接入合同

授权中心生成一段YUSHU1.接入文本，经营后台所有者粘贴并激活；新部署和旧授权升级使用相同入口。文本包含版本、授权ID、可信中心URL、公钥集合、实例ID、HTTPS部署origin、一次性激活码、有效期及中心签名证明。私钥、数据库和运营密码不交付。

经营后台仅接受服务端允许的可信中心（默认官方中心），从其HTTPS公共接口核对签名公钥，再验证接入证明及激活响应；不能信任文本自带公钥。手动输入作为高级备用。接入文本不进浏览器持久存储或日志，成功后清空。

旧授权在激活及原子保存连接之前继续有效；候选实例凭据使用独立固定目录，不覆盖旧凭据。失败可用同一接入信息幂等重试。激活后使用现有受控重启机制应用配置，UI提供明确状态和失败重试；不静默声称重启成功。续期沿用原授权/实例，已激活授权不重发接入包，换机按既有迁移流程。

开发验证仅使用虚构主体及生成密钥；不迁移或激活现有供应商，不部署生产。

## 操作步骤

授权人员在授权中心签发授权后，点击“复制接入信息”；已签发但未激活的授权也可从列表生成。把完整文本交给对应代理商。重新生成会撤销此前未使用的信息，有效期最长7天且不超过授权期限。

代理商升级到支持该功能的管理端后，以经营主体所有者登录，打开“授权与连接”，粘贴并点击“激活并应用”。无需下载、上传文件或逐项填写配置。成功后服务会尝试自动重启，稍后刷新并重新登录即可。非PM2部署需通过部署平台重启；页面会说明连接已保存并提供重试入口。员工不可激活。

当前为HTTPS部署接入协议；HTTP地址不能通过该流程激活。已经激活的独立中心实例继续使用原实例，不重新生成激活信息。激活信息视同一次性凭据交付，不要公开发布。

## 部署与兼容

先发布授权中心，再发布管理端。中心 `AI_LICENSE_PUBLIC_URL` 必须是其实际HTTPS根地址，默认官方地址。管理端默认信任官方授权中心；其他中心由部署人员通过服务端 `AI_AUTHORIZATION_TRUSTED_CENTERS` 配置允许的HTTPS根地址（逗号分隔），不能由粘贴内容自行扩展信任。

接入成功后，管理端在受控data目录持久化连接和独立实例状态。更新包不得包含或覆盖这些文件，迁机时按部署数据一起备份。连接文件不含激活码，实例状态含运行凭据，仍须限制访问。旧授权配置不删除，失败重试不覆盖它；迁移校验沿用环境或数据库中的原供应商ID。

## 隔离验证

管理端执行 `npm run check`、前端检查及构建。配套中心执行同样的后端和web检查。设置 `AI_LICENSE_CENTER_SOURCE` 指向对应中心源码目录，然后运行 `node scripts/test-authorization-onboarding-integration.mjs`，只使用内存中心、临时目录、虚构授权和临时生成密钥，无数据库及外部调用。

## 失效授权重新接入

经营后台区分配置已保存、待重启应用、授权有效、校验失效及中心暂不可达。删除、撤销、停用或到期后，可在授权页粘贴同一中心、同一HTTPS部署地址的新接入信息。网络超时只显示待核验，不当作已删除，也不显示连接有效。

中心原子核对新激活码和原实例凭据；旧授权仍有效、凭据/实例/域名不符、原授权已经接续给其他授权时拒绝替换。旧实例凭据仅由后台读取并通过HTTPS发送给原可信中心，不交给浏览器或授权人员。旧凭据缺失须先联系部署人员核对备份，不能仅凭同域名接管历史业务。

新授权保留中心签名的原业务身份，官方业务服务沿用原业务记录和既有身份映射。中心将原项目/构建额度登记接续到新授权，保留原预占ID和累计用量；原凭据与未使用激活码撤销，不能靠重建授权清零额度。经营后台的用户、订单、积分及项目数据库不重建、不清空。

候选激活和本地连接保存完成前不改写原连接，网络响应丢失可重试；成功后仍需重启应用。支持环境文件配置的历史实例及连接文件配置的新实例。只有配置文件存在不再代表授权有效。

发布顺序为：支持恢复的授权中心、支持原业务身份的官方业务管理端、下游管理端交付更新。中心公钥接口用 `authorizationRecovery:1` 声明支持恢复；不支持时管理端在消耗激活码前明确要求升级中心。

双仓隔离恢复测试：设置 `AI_LICENSE_CENTER_SOURCE`，执行 `node scripts/test-authorization-recovery-integration.mjs`。覆盖旧配置/新配置、连续重新授权、原授权有效时拒绝、错误凭据和域名、网络超时、激活响应丢失重试、资源原子接续及官方业务身份映射。
