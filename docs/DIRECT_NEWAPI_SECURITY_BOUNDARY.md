# 授权中心的源码、部署与信任边界

2026-11-02按负责人要求拆分为独立公开仓库，沿用既有许可证。

## 当前源码归属

| 部分 | 仓库与入口 | 交付与数据 |
| --- | --- | --- |
| 授权签发、套餐、运营账号、审计、通知与中心页面 | [YushuLicenseCenter](https://github.com/mengyuxuezhang/YushuLicenseCenter)，`cloud/license-center/server.mjs`，默认main | 独立中心代码、运行进程和MySQL库，独立构建 |
| 代理经营管理后台、部署客户端、官方业务鉴权 | [YushuHub](https://github.com/mengyuxuezhang/YushuHub)，本开发分支的`cloud/ai-admin/server.mjs` | 下游管理端包不含中心服务端或运营页面；保留接入、验签、公钥配置和公共协议 |

中心保留从YushuHub提取的相关文件历史，旧仓库的既有历史不重写。源码公开不包含运行密钥、运营账号资料、环境文件或真实数据库。独立仓库的README和docs/PROTOCOL.md是中心开发与安装入口；本仓库不再继续维护中心业务源码。

`src/repositories/authorization-state.mjs`等通用事务存储及协议辅助可在两仓保留，不等于保留签发系统。中心的参考客户端仅用于兼容性测试，实际代理运行客户端仍在YushuHub。能力键与协议改动必须做跨仓回归。

## 下游交付

中心源码、运营界面、初始化工具已从当前管理端分支移出。`scripts/pack-zip.ps1`增加专门的中心排除清单，分发审计拒绝中心服务、账号管理模块、运营页面和中心初始化工具。测试ZIP只用于隔离验收，不发布正式更新源。

拆分不会把源码控制权变成不可修改的软件限制。代理拿到完整管理端源码并控制服务器后，仍可以修改本地校验、信任地址或公钥。即使不提供中心源码，也不能承诺本地程序无法绕过许可判断。

## 官方信任边界

他们自建中心或自签凭证不会取得官方中心认可的授权，也不能增加New API余额。官方构建、更新和保护资源由官方服务器向其自行配置的可信中心核验；不能信任代理传入的中心地址、权限标志或自签凭证。官方生产部署仍应关闭旧授权兼容通道。

如果需要让本地每次模型调用都无法脱离官方控制，就需要改变完整源码交付或直连架构，将必要执行环节留在官方托管侧；本次没有引入新网关或反篡改系统。已经公开的历史不会因拆仓而变为秘密。

## 测试与部署

中心和管理端分别执行后端、前端、类型、架构及构建检查；跨仓集成测试使用独立MySQL与模拟供应商，管理端通过AI_LICENSE_CENTER_SOURCE引用独立中心测试源码。

测试中心切换新仓库代码时沿用原数据库、签名材料、凭据派生密钥、运营账号及环境文件，不重新初始化。迁移前后核对这些身份和数据指纹；保留旧代码和服务配置用于回退。正式发布及生产切换仍另行确认。
