## 当前发行基线

2026-11-09 核对的普通正式最新版是 **1.9.68**，官方 ZIP 为 `agent-ai-admin-v1.9.68.zip`，SHA256 为 `cf0cd1229ca5b03be2a2ce5df646c0e85728e3ed495f9e247d895e85714540ca`。公开 master 的 package 版本也为 1.9.68。本手册不将内部 `1.9.69-docker.1` 候选当作首迁前置版本。

当前单一首迁策略：已有后台先通过原有流程达到健康的 **PM2 1.9.68**，再迁入**同版本 1.9.68 镜像**，随后才升级到 catalog 明确批准的 Docker 版本。以后正式基线变化时，应重新核定合同及手册，不把 `latest` 标签当成版本合同。

1.9.68 基线的开发定向验证已完成：真实官方 ZIP 的 186 个镜像输入文件匹配；schema/migration 闭包与原已验合同一致；PM2→同版容器→后续候选→同版容器→原 PM2，两批数据、密钥、身份和源配置保持，直接新版首迁被拒。该新增基线仍待独立定向 QA，不能把历史 1.9.66 的原生验收改写成 1.9.68 已全部复验。

## 宝塔兼容方式与边界

| 项目 | 当前方式 | 需要维护者停下核定的情况 |
| --- | --- | --- |
| Docker Engine / Compose | 复用本机已有 Engine，调用 `docker compose` ≥2.30；不重装 Docker | 只有旧 `docker-compose`、使用远程节点/其他 daemon、依赖不齐 |
| 面板显示 | 官方说明终端创建容器可在 Docker→容器查看；Compose 另有入口 | 当前生成的是 root 受保护目录中的 `compose.json`，未实测所有版本的项目自动发现；不再次导入/编辑成第二个项目 |
| 网站 / Nginx | 首选保留原宿主 Nginx、域名、SSL、端口和反代 | Docker 网站入口不代表容器全集，也不能判断 Nginx 网络。bridge Nginx 的回环地址不可机械套用宿主回环目标 |
| 本地 MySQL | host 网络复用原本地 TCP 连接，无需迁数据库 | 远程/共享业务库、Unix socket 专用配置、未核定服务器/备份客户端版本 |
| 原 PM2 用户 | 当前控制器要求 root、单 fork、单受管实例 | 宝塔以 `www` 等用户运行的项目尚需独立用户适配，不能擅自提权或再启一份实例 |
| 面板守护 | 首迁前核对并停用“该后台”的旧复活器；其他应用不动 | 面板 Node 项目/计划任务会重新拉起旧写入者，或无法确定监督器归属 |
| 权限 / 持久目录 | 固定绑定原数据和日志；UID/GID1000、业务只读根、独立快照 | 宿主 UID1000 的其他使用者、外部目录/别名/符号链接未审；不全盘 chmod/chown |
| 版本管理 | 固定 digest、签名 catalog、审核计划、锁、收据与显式恢复 | 面板自动拉 latest/重建/改网络/删卷，会绕过控制器生命周期，不能作为升级入口 |
| 纯新部署 | 当前安装器不创建业务、空库/账号/初始身份或反代 | 现有 setup 需要健康 PM2 源；不能假称通用 Compose 导入等价于受管新装 |

面板可能能启动或重建容器，不代表这种动作满足本产品的迁移合同。手册只提供观察、原入口维护和已审终端步骤，不伪造应用商店模板或一键宝塔安装器。

## 实测与未实测的分界

- 已有控制器原生 Linux/systemd、Docker 重启、离线 CLI、CA 与恢复证据继续按固定候选验收范围使用，不重复全套。
- 新增 1.9.68 定向实验使用隔离 Docker/数据库、完整有效 center 缓存及 CLI；没有在该实验中重做在线中心、网页 UDS 或外部反代。
- 宝塔 UI 本身尚未实装验证，未给出“已验宝塔版本”。官方 9.3.0+ 教程和新版菜单资料只用于校准入口；截图不含面板版本，Nginx 版本也不是宝塔版本。
- 发行前应在获准环境记录面板版本、Engine/Compose、Nginx 位置/网络、PM2 用户、本地数据库/备份客户端、容器列表可见性及实际域名结果。此手册目前为待步骤审阅的候选。
- 非 root PM2、纯 Docker 新部署和迁移后配置/CA变更需要各自方案，不通过文档放宽现有校验。本轮没有新增这些功能。
