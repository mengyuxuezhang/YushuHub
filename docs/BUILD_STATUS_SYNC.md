# 构建状态的轻量同步

构建状态查询不应重复传输打包用的内嵌品牌图片。中央接口保留默认完整响应，为新版管理端提供显式轻量视图：

- `POST /api/center/builds/status` 的请求可带 `view: "status"`；按中央任务编号或原本地任务编号查询时均可使用。
- `POST /api/center/builds` 的受理响应也支持相同视图，避免品牌图片上传后再完整传回。
- 轻量响应保留任务状态、错误、日志、产物及摘要、执行节点、时间和来源关联；`brand` 仅含客户端模式与来源编号，并带 `brandMetadataOnly: true`。
- 中央查询在SQL投影时排除完整品牌图片，而非读取后才丢弃。原始品牌、打包输入及旧客户端默认响应保持完整。

消费端不能用轻量品牌替换原始完整品牌。已具备元数据的本地记录不因轮询重复回写品牌；历史缺失的模式字段可在保留原素材的前提下补齐。受理响应为轻量视图时，提交端保留本次原始品牌。

新版项目列表与构建列表使用 `sync=background&view=list`：请求先读取本地记录，后台更新中央状态，下次刷新显示权威结果。列表的SQL查询同样不读取完整图片。`sync=0`、显式同步和旧请求行为保持兼容。页面刷新和定时器共享进行中的同一平台同步；同步失败可再次尝试，不伪造任务完成。

上线顺序为中央构建中心先更新，再更新代理管理端。仅更新其中一侧不能得到完整优化：旧中心会忽略轻量视图，旧管理端仍会请求完整数据。

验证：后端195项、前端129项、分发8项、类型/架构/生产构建及烟测通过；覆盖大图片响应、原始素材保留、旧接口兼容、历史元数据修复、后台非阻塞和同步合并。只读对照同一条约5.94MB记录，轻量状态约117KB，减少98%，状态和产物字段一致。此记录描述代码验证，不代表已经部署或发布新版本。
