# 版本历史时间轴设计

日期：2026-10-28。开发分支：`design/release-history-timeline`，起点为最新 `origin/master` 的 `9098511`。本分支用于设计评审，未合入主分支或部署。

## 设计目标

代理可以回看全部已归档的管理后台与 Agent 更新记录，并快速找到某个版本或功能。共用现有全局样式库、主题变量、卡片、搜索框、按钮和 StatusBadge，不维护独立历史样式文件或字体配色。正文继承公共正文大小（当前为 16px）；纵向时间轴适合长更新说明、多个版本和窄屏浏览。

## 页面与交互

- “管理后台历史更新”和“Agent 版本更新记录”共用时间轴组件，在原有系统更新、构建机页面内替换历史展示区域。
- 顶部显示已收录版本数，并提供版本号、更新内容的全文搜索。
- 左侧按年、月筛选，右侧按发布时间倒序分组。日期与节点形成连续视觉线索，版本说明使用独立卡片。
- 最新版本用浅靛蓝背景和“最新版”标记突出；管理后台同时显示“当前运行”。预发布记录明确标注，不推断新增、修复等未经结构化标记的分类。
- 使用上一页、下一页和页码分页，支持直接输入页数跳转，每页可选 10、20、50、100 条，默认 10 条。切换月份或搜索条件时回到第一页，修改每页条数也回到第一页；数据减少时自动约束页码。搜索覆盖完整记录集，不局限于当前页。长说明可展开全文。
- 无日期的记录归到“日期未记录”；时间使用北京时间。加载、无历史和搜索无结果都有明确状态。
- 窄屏下月份目录变为横向选择，卡片与日期轴保留，避免整个页面横向滚动。

## 数据范围与兼容

- 管理后台完整版本档案现有 282 条，从 1.0.0 至 1.9.57；正式更新历史仍单独维护，未把测试或未发布候选混入正式升级清单。
- Agent 完整版本档案现有 329 条，从 1.0.0 至 3.0.74，包含当前 Git 仓库保留的早期代际和预发布版本。只导入版本信息、已归档更新说明、可展示的版本标签/提交说明、提交 SHA 与来源仓库/标签；不复制桌面端源码、凭据或内部运维文档。
- “全部”指 Git 和可信发布档案中可恢复的全部版本记录。正式说明优先；仅有 Git 信息的记录标记为“Git 版本记录”；没有正式说明时优先展示可确认的原始 Git 标签或版本提交说明，并明确注明原文来源，确无可展示信息时再显示缺失提示。已知未发布的 1.9.55 标记为“未正式发布”。日期若只能从版本提交恢复，会标注“日期取自 Git 提交”。缺失信息不凭版本号推断。
- 时间轴显式请求 `/api/self-update/status?history=all` 或 `/api/source-version?history=all`。已有请求默认继续返回最近 50 条，升级判断、权限和升级动作保持原有合同。
- Agent 本地积累档案保存全部已知记录，页面合并发布源、已积累档案及随包完整 Git 档案；按版本去重，排除高于当前发布源的未来版本。
- 自定义管理端更新源只使用该源的历史，避免混入官方档案。

## 本地预览

在 `web-admin` 目录运行 `npm run preview:history`，打开 `http://127.0.0.1:5189/admin/v2/history-preview.html`。

预览直接使用原来的系统更新与构建机页面及公共组件，不再维护另一套独立样式的预览外壳。旧的 `history-preview.html` 链接跳转到系统更新页面。

在另一个终端设置 `ADMIN_HISTORY_PREVIEW=1` 后运行 `npm run mock-api`，即可在开发服务的 `/admin/v2/updates` 与 `/admin/v2/workers` 原页面查看完整交互；该模式使用本地演示账号，不连接生产 API。

## 从 Git 补充版本档案

工具：`scripts/sync-release-archives.py`。先对来源仓库执行 `git fetch origin --tags`，再在本仓库运行：

```text
python scripts/sync-release-archives.py --admin-repo . --admin-legacy-repo <旧管理端历史仓库路径> --agent-repo <Agent-Desktop仓库路径> --agent-history-repo <YuAgent-Desktop历史仓库路径> --agent-history-repo <Agent-Desktop-Next历史仓库路径> --write
```

不传 `--write` 时只报告统计。工具合并 Git 中历次历史文件、版本字段变更、版本标签与历史发布清单。管理端以新仓库为主，旧私有仓库只读补充迁移前记录，不向旧仓库提交。

结果保存在 `docs/ADMIN_RELEASE_ARCHIVE.json` 与 `docs/AGENT_RELEASE_ARCHIVE.json`。版本去重，原有正式说明优先；标签可补齐准确的产品提交与链接。自定义更新源不混入官方管理端的 Git 档案。正式 `UPDATE_HISTORY.json` 及线上清单没有被这次归档操作改写。

升级包包含两份完整档案，归档恢复脚本和 Python 缓存不进入部署包。下游访问构建中心时可显式请求完整历史；普通版本检测仍使用有上限的响应，完整读取不会污染其缓存。


## 旧仓库复核与说明来源

按项目入口复核了早期 Web、1.0 桌面、2.0 早期方案及历史独立核心的版本说明来源。1.0 桌面仓库部分标签/提交包含具体功能说明；2.0 早期仓库也有单独的版本提交和标签说明。历史核心的已归档说明与当前仓库已有内容重合。Web 1.0 是独立形态，不能仅因版本号相同就混入桌面版本。

当前管理端 166 条有正式归档说明，另有 99 条补回原始 Git 说明；Agent 155 条有归档说明，另有 93 条补回 Git 说明。仍有 17 / 81 条未找到可展示的详细说明，其中包含只写版本号的提交。恢复出的旧仓库记录会保留在档案中，后续同步即使暂时没有旧仓库路径也不自动丢弃。
