# 版本历史时间轴设计

日期：2026-10-28。开发分支：`design/release-history-timeline`，起点为最新 `origin/master` 的 `9098511`。本分支用于设计评审，未合入主分支或部署。

## 设计目标

代理可以回看全部已归档的管理后台与 Agent 更新记录，并快速找到某个版本或功能。沿用现有靛蓝配色、白色卡片和轻边框；纵向时间轴适合长更新说明、多个版本和窄屏浏览。

## 页面与交互

- “管理后台历史更新”和“Agent 版本更新记录”共用时间轴组件，在原有系统更新、构建机页面内替换历史展示区域。
- 顶部显示已收录版本数，并提供版本号、更新内容的全文搜索。
- 左侧按年、月筛选，右侧按发布时间倒序分组。日期与节点形成连续视觉线索，版本说明使用独立卡片。
- 最新版本用浅靛蓝背景和“最新版”标记突出；管理后台同时显示“当前运行”。预发布记录明确标注，不推断新增、修复等未经结构化标记的分类。
- 首次显示 12 条，继续加载更早版本；搜索覆盖完整记录集，不局限于当前已显示的条目。长说明可展开全文。
- 无日期的记录归到“日期未记录”；时间使用北京时间。加载、无历史和搜索无结果都有明确状态。
- 窄屏下月份目录变为横向选择，卡片与日期轴保留，避免整个页面横向滚动。

## 数据范围与兼容

- 管理后台档案已有 126 条，从 1.0.68 至 1.9.57。
- Agent 发布档案补齐为 143 条，从 3.0.0-beta.68 至 3.0.71；最新版本已与官方清单核对。仅复制版本号、发布时间和公开更新说明，不导入桌面端源码或内部运维资料。
- “全部”指全部已收录记录；缺失的发布记录需由可信档案补充，不生成虚构历史。
- 时间轴显式请求 `/api/self-update/status?history=all` 或 `/api/source-version?history=all`。已有请求默认继续返回最近 50 条，升级判断、权限和升级动作保持原有合同。
- Agent 本地积累档案保存全部已知记录，页面合并发布源、已积累档案及随包档案；按版本去重，排除高于当前发布源的未来版本。
- 自定义管理端更新源只使用该源的历史，避免混入官方档案。

## 本地预览

在 `web-admin` 目录运行 `npm run preview:history`，打开 `http://127.0.0.1:5189/admin/v2/history-preview.html`。

预览页可切换两个产品，直接使用同一业务组件和已归档记录，所有筛选与加载按钮可操作。预览入口不加入生产菜单，也不进入默认生产构建入口。

## 验证

前端 132 项测试、后端基础与历史专项检查、类型检查、架构检查和生产构建通过。浏览器实际验证超过 50 条范围的旧版本搜索、月份筛选、分批加载以及 1440px / 390px 布局；新版指纹构建产物随本分支保存。
