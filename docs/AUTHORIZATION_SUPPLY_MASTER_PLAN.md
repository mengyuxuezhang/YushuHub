# 授权中心、代理供货与分级计费总规划

版本：1.0；最后更新：2026-10-30。状态：已确定目标，开发与隔离验收中，尚不具备生产切换条件。

本文件是跨仓库业务目标与验收规则的权威说明。[当前进度](AUTHORIZATION_SUPPLY_STATUS.md)记录实际完成情况；[开发说明](INDEPENDENT_AUTHORIZATION.md)记录已经实现的接口及配置。计划条目不等于功能已经实现。后续开发者应先读这三份文件及各仓库AGENTS，不能仅凭聊天记录、测试数量或某个阶段提交宣布项目完成。

## 1. 范围与决策记录

- 建立独立授权中心，统一签发一级和二级授权，原构建中心退出授权签发。
- 一级支持部署管理端源码；不包含桌面端源码资格。二级共用一级服务器、域名和数据库，按组织隔离，不可独立部署。
- 一级自定义模型模式和固定模型模式分别建模；二级继承一级供货模型，只能加价。
- 保留用户、会员、支付、积分、兑换码、通知、品牌项目、构建发布、更新和专家/Skills/MCP分发；仅按新规则取消本地转授权。
- 2026-10-29确认：当前无存量二级、无下游私有音色历史。无需这两类历史迁移；跨一级迁移工具延期。新二级隔离与新私有音色功能本身仍需实现、验收。
- 2026-10-30确认：复用现有New API聚合层，并建立独立二开仓库`okpa-new-api`，自己管理源码、构建、镜像和版本；保留上游来源和选择性修复同步能力。
- 本轮包含开发、隔离部署测试、迁移与对账工具。正式生产切换、真实经营数据迁移和正式更新源发布需按发布约定执行。测试服务器的授权与真实供应商调试授权不自动扩展到其他生产系统。

## 2. 服务、仓库与数据归属

| 服务 | 维护位置 | 权威数据与职责 |
| --- | --- | --- |
| 主网站 | 现有官网仓库 | 产品介绍及入口，非授权/资金来源 |
| 独立授权中心 | YushuHub独立入口 | 代理、套餐版本、授权码、部署绑定、签名、撤销、审计；独立数据库 |
| 官方代理供货服务 | YushuHub独立入口 | 官方目录、供货价、一级预付钱包、预占、请求、结算及对账；独立数据库 |
| New API聚合层 | okpa-new-api | 渠道、协议适配、官方技术账户额度及上游消费日志；原New API数据库 |
| 浏览器/CLI网关及渠道运维 | web-llm-gateways | 网关、隧道、实例、New API运维与受控调试工具 |
| 原构建与资源中心 | 现有官方服务/YushuHub相关模块 | 构建、产物、资源和交付数据保留，改查新中心授权 |
| 一级管理端 | YushuHub | 一级经营、二级组织、终端用户、二级供货钱包、自接模型、用户积分 |
| 二级后台 | 一级管理端内 | 共库；会话确定组织及数据范围 |

部署域名与业务职责分开：已有主站、New API、构建中心继续分工；授权中心建议独立域名，供货服务可以独立域名或受控入口。具体DNS、证书、服务器位置由部署阶段确认，域名建议不代表已部署。

官方模型链路：终端 → 一级服务器解析组织并预占本地权益 → 供货服务校验授权、预占一级余额 → New API或直连供应商 → 结算与事件对账。

自接链路：终端 → 一级服务器解析组织并预占本地权益 → 一级自有供应商 → 本地结算。一级自接成本由一级承担；二级仍按一级供货价结算。

### 单一余额权威

代理预付款只在供货钱包记账。New API中的官方技术账户是上游调用账户，不是第二份代理钱包，不得把同笔代理充值同时生成两份可支用余额。现有New API直接客户继续沿用原账户，不能静默并入代理系统。New API原始quota不是六位人民币；转换须依据已核实的单位、币种及版本，仅用于技术成本核对，不能直接覆盖代理账本。

## 3. 代理、套餐与能力

代理层级、模型模式、套餐版本是三个独立维度。

| 能力 | 一级自定义 | 一级固定 | 二级 |
| --- | --- | --- | --- |
| 管理端源码部署 | 是 | 是 | 否 |
| 自有供应商/密钥 | 是 | 否 | 否 |
| 官方模型 | 按中心授权 | 按中心授权 | 继承一级供货目录且受中心授权约束 |
| 定价 | 自接自由，官方加价 | 官方基础上加价 | 一级供货价上加价 |
| 用户/会员/支付/积分/兑换码 | 开放 | 开放 | 开放 |
| 品牌/构建/资源市场 | 按中心套餐和额度 | 按中心套餐和额度 | 按中心套餐和额度 |
| 签发代理授权 | 否 | 否 | 否 |
| 管理直属二级供货和经营状态 | 是 | 是 | 否 |
| 系统更新/服务器/存储配置 | 是 | 是 | 否 |

基础模板为`first-custom`、`first-fixed`、`second`，套餐版本不可覆盖；修改模板不静默改变旧授权，先预览影响，再显式发布授权变更。当前开发默认项目1、累计构建10只是模板初值，正式套餐价格、期限及额度待运营确认。

一级可选择对二级供货的模型，二级可启停其中模型；二级不能换实际模型、供应商、密钥、计量项或调用地址。固定一级仅可调整允许的展示项、启停和加价。

## 4. 签发、激活及生命周期

### 4.1 身份与激活

- 中心创建一二级授权档案并签发一次性激活码，默认7天，只存哈希；遗失作废重发。
- 一级绑定备案域名及生产实例，获得可轮换实例凭据。默认一个生产实例。
- 二级在中心预绑一级组织和实例，只有对应可信一级可兑换；重复请求返回原身份，不重复建组织。
- 二级管理员以24小时一次性邀请设置初始密码；中心不持有经营后台密码。
- 续期沿用组织及授权身份，不重置钱包和累计用量。一级不能本地创建二级、改中心期限、追加能力或恢复中心停用。
- 员工创建保留，员工不是新代理主体，不能借岗位或员工账号绕过代理规则。

分别管理激活码（未使用/已使用/过期/作废）、授权（正常/暂停/到期/撤销）、经营（正常/一级暂停供货/欠费）；经营状态不得覆盖中心授权状态。

### 4.2 权限与隔离

有效权限由中心能力、层级限制、员工岗位及数据范围共同决定。菜单、后端API、官方服务执行同一约束。二级可被中心授予独立收款等适用能力，不简单取一级菜单交集；模型、供货及总额度仍受一级约束。

资源归属以服务端会话为准，拒绝伪造组织ID。二级仅访问本组织用户、订单、积分、项目、报表；一级默认仅看供货及经营汇总，终端明细查看/代操作需单独权限，并记录操作者及目标组织。

### 4.3 校验与失效

- Ed25519凭证包含密钥编号、版本、实例绑定、能力、有效期；支持签名密钥轮换。
- 在线实例每60秒检查变更。官方服务凭据限定用途、短期有效，缓存最长60秒。
- 新激活和敏感变更必须在线。网络故障可使用持久化签名授权，宽限最多24小时且不超过授权到期时间。
- 明确拒绝/撤销立即持久化清缓存，不能在随后断网时恢复旧授权；一级失效阻止二级新经营请求，恢复后重算二级状态。
- 到期前30/7/1天提醒，只发尚未错过窗口，去重并有真实投递及监控。
- 到期或超宽限关闭新充值、购买、调用、构建；保留登录、账单、续期、导出及退款处理。已受理任务需独立恢复/对账权限，不能伪装成有效新调用。
- 换机由中心迁移绑定，最多24小时临时双实例，之后撤销旧实例。当前立即轮换实现不能冒充此完整目标。
- 中心运营账号强制MFA，签发、撤销、迁移、调账审计留存。

## 5. 模型、价格及三类账本

### 5.1 模型与价格

官方密钥仅在官方供货或聚合侧受控保存；二级不可读取一级密钥、预览和原始连接配置。覆盖现有文本、搜索、图片、语音及异步任务；开发中能力继续标为开发中。

官方维护基础供货价；一级对终端售价与对二级供货价分别配置，默认同价；二级在一级供货价上加价。按每个计费项记录非负加价额，允许零加价。一级自接模型自行定基础售价、供货价并另记成本。

普通上游调价至少提前24小时，保留各级加价额并联动下游价；紧急故障通过停供处理。请求受理时锁定整条价格链、汇率、积分比例、用户折扣及倍率版本，长任务仍按旧快照结算。终端赠送、会员优惠或消费倍率不得减免已发生上游费用；差额体现为营销补贴。

New API动态价格、分时计价及技术账户原始quota需作为可追溯成本证据，不自动改变官方供货价，不重算历史快照。

### 5.2 账本与金额

| 账本 | 权威位置 | 内容 |
| --- | --- | --- |
| 一级官方供货账 | 官方供货服务 | 充值、预占、消费、退款、欠款 |
| 二级上游供货账 | 一级服务器 | 二级充值、按一级供货价结算 |
| 终端积分账 | 所属一级服务器 | 充值、赠送、会员权益及消费 |

上游余额用人民币六位十进制定点数，禁止浮点算账；积分规则延续并版本化，不改历史记录。首版代理充值线下收款后审核入账，无提现或自动分账；终端支付保留。

原流水不可修改/删除，纠错使用关联冲正；余额、预占、流水同库事务更新，充值回调、人工入账、用量结算都有幂等键。人工增加终端积分不得增加上游余额。报表区分销售、供货支出、价差、补贴和待结算；充值不直接计为模型利润。

正式存储必须拆分钱包、预占、请求、流水、结算、幂等命令、事件表，设唯一约束及事务锁顺序。当前单行JSON聚合只用于开发验算，需有显式迁移、期初核对、并发/容量/恢复测试后才能进入生产供货。

## 6. 请求受理、故障和对账

1. 校验授权、组织、模型和余额，生成全链路请求ID及不可变价格快照。
2. 按可执行上界预占用户积分、二级余额和官方一级余额。
3. 调用模型，记录实际用量、供应商结果及上游请求编号。
4. 按实际用量结算，释放剩余预占；失败/取消仅结算已确认可计费用量。

文本必须有限输出；异步规格必须可估费用。没有计费上界不能放行。跨服务使用持久化事件、重试及对账，不使用跨库事务。

结果未知、流式断连或网络超时不立即释放可能已收费预占，先查原请求或人工核对；禁止盲目重发。重复回调、超时重试、重启不得重复扣费。计量尾差形成欠款、阻止新请求，充值先抵扣。

New API响应头编号在读正文前持久化，关联本地请求。请求编号不是幂等保证；无日志不等于无费用。二开目标是在此基础上增加受限用量查询、可靠结算事件与异步恢复能力；供应商已受理但不可查询时仍保留人工处理路径。

## 7. 项目与构建额度

保留原口径及已用量。项目限制有效项目数；构建为授权周期内累计受理次数，普通续期不重置。同任务内部重试不重复计次，主动新建另计。成功受理时占用，项目释放与构建累计区别处理。

二级同时受自身及一级总额度限制；明确`none/limited/unlimited`，不再用0混表达未授权和无限。实际项目创建及构建受理必须原子占用，不能仅实现独立额度API而未接业务路径。

## 8. New API独立二开基线

- 仓库`okpa-new-api`保存New API源码和二开构建；`web-llm-gateways`继续负责网关和运维；不重复放两份New API业务源码。
- 初始基线官方`v1.0.0-rc.47`，提交`e835b1bfc43b565d625537830dbfb19328925134`。保留许可证、版权、NOTICE、模块路径和上游来源。
- `origin`为自有仓库，`upstream`为官方；安全和渠道修复先在集成分支评估，禁止自动覆盖生产或无审查追随latest。
- 自有版本、镜像与发布流程可追溯到源码提交及上游基线；镜像按摘要部署，保留构建证明、日志和回滚包。
- 首先完成自有源码构建及隔离回归，再开发请求关联、受限用量查询、结算事件、流式中断和异步恢复。不得默认把New API的原钱包提升为代理钱包权威。
- 保持原直接调用客户及公开协议兼容；独立源码维护不等于已部署、已迁移数据库或已替换正式镜像。

## 10. 历史一级迁入与下游在线升级

导出旧一级、能力、期限、额度、部署和审计，生成差异。保留组织/用户ID，建立中心代理映射。无绑定、旧无限、超配、无归属逐项审核，禁止静默扩权、丢记录或清零已用量。

保留积分、会员、订单、项目、流水。供货钱包初始0，既有预付款凭证审核后生成期初流水；不把终端积分换代理余额。模型价格、积分比例、折扣形成快照；与供货底价冲突先处理再切换。旧供应商Token不能兑换新激活码，切换时轮换凭据。

升级步骤：备份 → 显式legacy过渡 → 正式更新包校验/安装/重启/重新登录 → 新表迁移和授权登记 → 影子权限及资金额度核对 → 中心激活 → 单实例切换。旧版源码升级演练通过不等于全量授权迁移已完成。

同一实例同一时刻只有一套计费系统。第一笔新真实结算前可回旧模式；之后只可回兼容新账务的代码版本，不可恢复旧数据库快照覆盖新增流水。先内部实例，再试点一级及其新建测试二级，最后分批切换。跨一级交接延期，启用该需求前再实现暂停写入、账务交接、校验、重绑及旧访问撤销。

## 12. 必测与运行保障

- 授权：重复/过期/错绑激活、撤销、续期、迁机、缓存拒绝、断网、重启恢复及签名轮换。
- 权限：三类代理逐菜单逐接口、伪造组织、员工提权、旧创建入口；一级明细查看/代操作审计。
- 模型：固定不可换供应商，二级不能越目录或取密钥；官方和自接分别结算；现有客户端字段和音色资源契约。
- 账务：并发余额不足、重复回调、释放/尾差/欠款、冲正、退款、断流、异步失败、未知结果、跨服务重启恢复。
- 价格：复合计费项、零/负加价、24小时通知、逐级联动、旧快照、优惠及营销补贴。
- 额度：上下级总量、并发项目/构建、重试去重、续期不清零、旧无限映射。
- 升级：既有一级权限对照、权益资金守恒、异常追踪、回滚不丢新流水；正式包摘要、前端指纹及运行版本。
- 旧能力：用户、会员、支付、兑换码、通知、模型、构建发布、更新及专家/Skills/MCP分发回归。

执行YushuHub的npm run check及领域测试；前端改动还需类型、测试、架构及生产构建并提交产物。New API遵循自身AGENTS测试规则，数据库变更必须验证真实SQLite/MySQL/PostgreSQL及迁移幂等，不能只测一种。默认模拟供应商；真实调用记录授权范围及非敏感证据。

监控授权同步延迟/拒绝、结算重试、预占滞留/账龄、对账差异、债务、事件积压、未知供应商结果及服务错误；提供告警、人工处理、备份恢复和审计保留操作。7天试点需有起止记录、指标和未解释差异清单，不能用单次验收替代。

## 13. 后续开发纪律

每次交付更新进度表、测试证据、剩余缺口和下一项；规则变化更新本总规划并记录日期及决策依据。未经确认的域名、价格、正式套餐和试点实例留在待决策栏，不能自行当成生产配置。

官方侧应控制模型、构建和保护资源访问；一级持有管理端源码，自接能力以软件校验、审计和许可约束，不承诺无法修改源码。生产秘密、用户资料、运维地址和数据库副本留在受控环境，源码文档只留脱敏协议和证据摘要。
