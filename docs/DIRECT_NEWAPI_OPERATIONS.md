# 独立授权与直连 New API：配置、升级和回退

本手册以[简化规划](DIRECT_NEWAPI_PLAN.md)为准。旧供货方案仅在旧分支保留；此版本没有二级代理、代理供货账本、独立模型网关或专用 New API 结算协议。完整源码由代理控制时不能承诺地址不可改写，官方版本通过软件策略、中心凭证及许可约束执行。

## 服务与授权矩阵

| 能力 | 自定义服务商 | 固定服务商 | 员工 |
| --- | --- | --- | --- |
| 独立管理端部署 | 中心签发 | 中心签发 | 共享所属主体 |
| 文本服务商 | 按套餐和岗位维护 | 独立官方记录，固定 `https://api.okpa.cn/v1` | 同时受套餐与岗位约束 |
| 文本 Key、模型、终端售价 | 本主体配置 | 本主体 New API Key、自选模型和售价 | 须有相应岗位权限 |
| 图片、语音、独立搜索 | 保留主线方式 | 保留主线方式 | 原有权限不变 |
| 用户、支付、积分、会员、兑换码 | 主线流程 | 主线流程 | 按岗位和本主体范围 |
| 项目、累计构建 | 中心明确 none/limited/unlimited | 同左 | 共用主体额度 |
| 授权签发、续期、暂停、撤销、换机 | 仅中心运营，强制 MFA | 同左 | 无权限 |
| 创建其他代理、转授权、下级钱包 | 无此业务 | 无此业务 | 无此业务 |

功能套餐使用不可变版本；`modelMode` 独立于套餐。测试基础套餐为项目3、累计构建10，标注非正式经营配置。变更模板不影响已发授权，须在中心预览并显式发布。续期保留授权 ID、实例身份、项目占用及累计受理构建数；失败任务内部重试不另计数，主动提交新任务另计。

## 独立中心安装

使用独立 MySQL 数据库，不能复用经营库。中心只处理授权、低频资源额度和通知，不接收模型内容、不代扣上游费用。

1. 创建独立库和最小权限数据库账号。生产签名材料、数据库密码、运营账号资料及 Webhook 放在仓库外受控目录。
2. 在受控会话设置至少16位的 `AI_LICENSE_BOOTSTRAP_PASSWORD`，运行 `node scripts/authorization-init.mjs <受控空目录> <运营账号>`。脚本生成 Ed25519 密钥、实例凭据派生密钥和带密码哈希/TOTP 的运营文件，拒绝覆盖已有材料。把 TOTP 秘密导入可信验证器，随后清除引导密码环境变量。
3. 在受控环境文件配置下表，执行 `node --env-file=<受控环境文件> cloud/license-center/server.mjs --migrate`，再用相同环境启动 `cloud/license-center/server.mjs`。环境文件不提交 Git。
4. `npm run license-center:build` 生成 `web/license-center/index.html` 及指纹资源；中心入口为 `/license-center/`。默认监听回环地址17881，通过 HTTPS 反向代理公开。运营端默认使用密码及动态验证码；隔离体验可配置图片验证码模式，会话30分钟；令牌不存入浏览器持久存储。

| 环境项 | 含义 |
| --- | --- |
| `AI_LICENSE_DB_HOST/PORT/USER/PASSWORD/NAME` | 独立中心 MySQL，NAME 必填 |
| `AI_LICENSE_PRIVATE_KEY_FILE` | Ed25519 私钥文件 |
| `AI_LICENSE_PUBLIC_KEYS_FILE` | `{密钥编号: PEM公钥}` 文件 |
| `AI_LICENSE_KEY_ID` | 本次签名密钥编号，见初始化生成文件 |
| `AI_LICENSE_CREDENTIAL_KEY_FILE` | 实例凭据派生密钥文件，须稳定备份 |
| `AI_LICENSE_OPERATORS_FILE` | 密码哈希和 TOTP 文件，切换体验模式也保留原 TOTP 材料 |
| `AI_LICENSE_OPERATOR_LOGIN_MODE` | 默认 `totp`；测试体验设为 `captcha`，密码加一次性图片验证码；正式恢复 `totp` 后重启 |
| `AI_LICENSE_HOST/PORT` | 默认127.0.0.1:17881 |
| `AI_LICENSE_WEBHOOK_FILE` | 可选通知配置文件，运行时重新读取 |

2026-11-02按负责人要求，当前测试中心临时使用 `captcha`。图片验证码5分钟有效，绑定请求来源，错误或成功提交后均不可复用，并保留登录/验证码获取限流。恢复动态验证只需把该环境项改为 `totp`（或删除该项）并重启中心，原运营账号和TOTP秘密保持；不同模式的旧会话会失效。前端自动读取服务端登录方式，浏览器不能自行关闭动态验证。

Webhook 文件格式为 `{"enabled":true,"url":"https://example.test/webhook"}`，支持飞书文本消息协议。每分钟扫描30/7/1天提醒，错过创建窗口的不补发；失败持久重试，已确认事件不再发送。换地址只需替换受控配置文件。通知为至少一次投递，接收器可按 `Idempotency-Key` 去重；网络结果不确定时可能重复通知。管理界面可查看发送状态，不展示地址中的秘密。

## 代理配置和固定模式

新安装默认 `AI_AUTHORIZATION_MODE=center`，没有有效中心授权仅保留登录、账单及续期相关入口，不授予默认全权限。

- `AI_LICENSE_CENTER_URL`：独立中心 HTTPS 根地址。
- `AI_LICENSE_INSTANCE_ID`：本生产实例唯一稳定 ID。
- `AI_ADMIN_PUBLIC_URL`：与中心预登记一致的 HTTPS 域名。
- `AI_LICENSE_PUBLIC_KEYS_FILE`：由可信渠道交付的中心公钥集合。
- `AI_LICENSE_STATE_FILE`：持久部署授权状态文件，默认 `data/deployment-license.json`；备份并限制文件权限。

所有者在“授权与连接”兑换激活码。激活码默认7天、只保存哈希、一次兑换；同一次请求重试不重复创建身份。续期直接更新原授权，不能换码重建主体。

固定模式激活后，先预览文本切换，核对模型列表并确认。系统新建独立 `system-text-okpa` 连接，文本模型和报价关联改指向它；原供应商记录及 Key 保留，原第三方 Key 不复制、不复用。图片、音频、独立搜索不移动。为新连接填写代理本人在 New API 创建的 Key，选择模型并维护终端售价。需要上游余额时直接到 `https://api.okpa.cn` 注册充值，经营后台积分与上游余额分别维护。

官方版本执行文本调用、连通测试和文本任务时重新解析固定地址，只允许当前 `/chat/completions` 协议路径，拒绝绝对端点及重定向。数据库中修改官方记录 URL 不改变实际文本目的地。自定义模式保留其他服务商能力。没有中心目录、供货底价或强制同步上游售价；本地积分流水不代表已核实的 New API 成本或利润。

## 旧部署升级

1. 保留旧方案归档数据及证据。先备份完整经营库、部署配置、`data` 内支付/模型凭据/保护资源密钥及当前代码；确认可恢复。
2. 在**升级前**为已有部署显式配置 `AI_AUTHORIZATION_MODE=legacy`，沿用旧授权完成更新。新安装不能借缺省配置取得全权限；旧部署升级需要运营者主动设置该兼容开关。
3. 使用仓库外 MySQL 配置文件运行 `node scripts/authorization-upgrade-inspect.mjs <数据库配置JSON> <新建的受控报告JSON>`。工具只读，不导出密钥；报告列出身份、项目、模型、用户积分合计、订单数、密钥数量和异常，并生成期初额度片段。
4. 意外发现 `agent_level=2` 时，预检和新版本启动都会明确报错，不能自动删除、转换或扩权。其他异常须审核；不开发二级迁移兼容层。
5. 核对旧授权期限、功能、无限额度和已用构建数量。工具的构建数来自现存 `ai_builds`；若历史曾被删除，必须凭旧中心/审计补齐，不能将缺失历史当作0。项目清单必须与冻结写入后的实际库一致。单次期初清单超过2000条时停止，不得截断后签发。
6. 中心签发时合并报告的 `issueFragment`：`initialUsage` 保存已用总数，`initialResourceIds.projects` 登记既有项目 ID，避免首次编辑双计数，并允许删除后释放容量。累计构建基线不能通过续期清零。审核后预登记模式、域名及套餐，不自动批准经营价格。
7. 冻结经营写入，重新只读导出核验，再配置中心公钥/实例与域名，切换 `AI_AUTHORIZATION_MODE=center`，重启并由所有者激活。核对原管理员和员工可登录，用户、订单、积分、会员、项目、报价及加密 Key 保持。按上一节显式预览固定文本切换。
8. 在隔离副本验证两类授权、支付回调幂等、余额不足、非文本调用、构建和保护资源后，再申请生产切换。此分支没有发布到正式更新源，也没有修改版本标签；不能据此声称下游已能通过正式更新源获取新版本。

隔离演练已验证真实1.9.58通过在线ZIP更新到本分支1.9.59：下载摘要、包内版本、PM2新进程/端口、前端资源和经营数据保持均通过；随后完成中心激活和固定模式切换。现网已是1.9.59的部署，需要正式发版提升版本号并发布官方清单，才能通过在线更新发现本改造。本分支提交本身不会触发下游更新。

Windows仅虚构项目的3.0.78→3.0.79升级验证了客户端自主检查、下载校验、安装和重启，以及身份与测试数据保持。安装范围为新测试账号，实际安装目录由向导确认。测试候选为未签名实验室构建；生产签名和正式发布另行执行。

## 官方构建、资源和更新服务

官方业务服务配置中心 URL，默认使用中心鉴权；旧兼容服务须显式配置 `AI_OFFICIAL_AUTHORIZATION_MODE=legacy`，仅在过渡阶段保留。旧“供应商接入”页面只读查看业务记录，所有签发、修改授权、重置 Token 等写请求都被拒绝。

代理的官方构建中心配置在中心模式下只需 HTTPS URL；请求使用中心短期用途令牌，不依赖原 Supplier Token。构建、保护资源、更新分别使用用途受限凭据，官方服务实时向中心校验当前授权版本和绑定。项目及构建由中心原子占用，经营库持久保存本地资源意图与业务写入，断线或重启后恢复确认/释放，已受理构建不退计数。没有跨库事务或代理资金账。

在线实例每60秒同步。明确401/403拒绝会持久清除有效凭证，之后断网不能恢复旧缓存。一般网络故障仅使用持久签名凭证，最多24小时且不超过授权期限。新激活、官方业务和敏感授权操作必须在线。轮换实例支持0–24小时临时双绑定，并可提前撤销旧绑定。

签名轮换须先把新公钥加入可信公钥集合并部署，再更换中心签名编号/私钥；旧公钥至少保留到旧短期凭证和24小时缓存全部失效。私钥和派生密钥不能随意重新生成，丢失时按事故恢复处理。

## 回退

生产切换和正式发布另行确认。升级演练可回退保留的代码版本及显式旧授权配置，但不能覆盖切换后新增的用户、订单、积分、支付状态或账务流水。固定切换前备份模型关联与配置；恢复关联须审核并保留新 Key、历史记录和所有新增交易，禁止拿旧数据库快照覆盖经营变化。中心资源累计计数不能通过回退或重发授权消除。

旧复杂方案源码、测试数据及观察记录保留。负责人已批准停止并禁用旧 TEST 服务，旧连续观察结束；license.okpa.cn 已作为简化方案的隔离验收入口，未执行生产切换。实际测试部署、暂时凭据和服务停止/恢复证据在仓库外受控交接记录维护。
