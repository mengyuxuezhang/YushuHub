# 分级供货账务存储、迁入与恢复

更新：2026-10-30。业务规则见[总规划](AUTHORIZATION_SUPPLY_MASTER_PLAN.md)，剩余门槛见[进度](AUTHORIZATION_SUPPLY_STATUS.md)。本文说明当前独立表实现及受控切换步骤，不代表全项目已达到生产发布标准。

## 数据与事务

官方供货服务使用`official-v2`账本；一级本地供货使用`commerce-v2`账本，各自位于其原本独立的数据库。账本名称是存储版本和隔离键，不是额外钱包。

| 表 | 职责 |
| --- | --- |
| accounting_books | 已激活账本、来源、迁入摘要及时间 |
| accounting_locks | 钱包/请求/命令/凭证的持久锁身份 |
| accounting_wallets | 权威余额及预占，DECIMAL(18,6) |
| accounting_requests | 请求归属、状态、快照、结果、上游凭证、恢复排期 |
| accounting_holds | 每请求供货金额/终端积分预占及释放标记 |
| accounting_entries | 不可变供货流水、充值凭证及关联冲正 |
| accounting_settlements | 每请求唯一结算记录 |
| accounting_commands | 人工入账、冲正命令的唯一幂等结果 |
| accounting_outbox | 持久化结算事件、确认状态及重试排期 |
| accounting_settings | 供货配置、加价及价格版本 |

余额字段以原生DECIMAL列为准，JavaScript使用BigInt定点运算；JSON仅承载单实体快照及兼容字段，不再把整个业务账本放在一行。标识使用二进制、区分大小写的ASCII列，避免MySQL默认排序规则混淆大小写不同ID。

资金操作使用READ COMMITTED事务，按固定顺序获取钱包、请求、命令及凭证范围的锁，只载入相关记录，网络推理在事务之外。不同钱包无需争抢同一聚合行；同钱包的余额/预占更新串行，死锁或锁等待超时最多重试两次，重试回调仅含数据库操作。只读账单使用一致性快照，列表有上限和总数，不读取整个历史账本用于每次请求。

充值凭证摘要、请求ID、幂等命令、冲正来源和结算分别有数据库唯一约束。流水、结算和已完成命令有UPDATE/DELETE拒绝触发器；纠错新增关联冲正。请求归属、原始预占和价格快照不可通过业务存储修改。

本地用户原有`ai_end_users`、`ai_credit_ledger`继续是终端积分来源；用户预占/退款、二级供货预占/扣款、本地请求及事件在同一连接事务提交。迁入不更新用户积分，不从用户积分产生上游余额。

中心授权状态、网关MFA会话不是资金账。授权中心暂保留原聚合存储；网关运营认证迁到单独的`official-v2-operators`记录，保留旧MFA计数与会话哈希。

## 明确初始化与旧账迁入

运行时不执行DDL，也不默认回退旧JSON账务。未初始化返回明确错误；旧数据存在时普通初始化拒绝开一个空的新钱包。

准备：明确目标数据库、停新请求并完成或登记在途任务，停止所有旧写进程，备份数据库和凭据。备份应包含触发器。以下工具不会自动读取生产.env，连接配置由受控环境注入。

| 目标 | 配置前缀 | 旧记录 |
| --- | --- | --- |
| 官方供货 | AI_GATEWAY_DB_HOST/PORT/USER/PASSWORD/NAME | state-v1 |
| 一级本地 | AI_AUTHORIZATION_LOCAL_DB_HOST/PORT/USER/PASSWORD/NAME | commerce-v1 |

```text
# 写操作前显式设置 AI_ACCOUNTING_MIGRATION=approved
node scripts/accounting-migrate.mjs gateway init
node scripts/accounting-migrate.mjs local init

# 有旧账时使用import代替init（先备份并停止旧写进程）
node scripts/accounting-migrate.mjs gateway import
node scripts/accounting-migrate.mjs local import

# 保持停止受理状态，验证迁入；差异退出码2
node scripts/accounting-migrate.mjs gateway verify
node scripts/accounting-migrate.mjs local verify

# 恢复受理后，检查当前账本守恒；不再用迁入时摘要要求现账不发生变化
node scripts/accounting-migrate.mjs gateway audit
node scripts/accounting-migrate.mjs local audit
```

新表DDL在显式命令中执行；资金迁入和开账标记在单库事务内完成。工具核对钱包=历史流水之和、预占=未结算请求持有额，再导入原始ID、请求、快照、幂等命令及事件。异常不静默补钱或丢弃；修复并核对旧数据后再导入。失败可能留下空表/触发器，不会激活部分钱包。重复执行只返回原迁入结果，不重复生成充值。

迁入成功后，旧记录保留快照并写入cutover标记。数据库触发器拒绝对已标记旧行的UPDATE/DELETE，因此不认识标记的旧程序也无法继续更新聚合资金。原始流水、结算和命令同样禁止改写。不要删除这些触发器来运行旧代码。

网关入口兼容显式`--migrate`，有旧账时须`--migrate --import-legacy`；本地`authorization-local-migrate.mjs`仍要求原来的批准变量，并可用`--import-legacy`。两种入口调用同一迁入实现。本地邀请表仍由本地授权迁移命令创建。

完成verify后配置center模式并启动新版本。已有`commerce-v2`账本的当前管理端拒绝以legacy模式启动，防止环境误配回到旧计费。预切换无损回退工具仍属P5待交付；目前不得直接改.env绕过保护。受理新结算后只能回退兼容新账务的代码，不能恢复旧库快照覆盖新流水。

## 恢复与未知结果

网关启动及每60秒扫描最多50条过期受理记录，默认5分钟阈值：

- `reserved`尚未通过持久化`start`发送屏障，确认未调用供应商，原子结算0、释放预占并生成结算事件；后续start不能再次发送。
- `running`已通过发送屏障，不能判断是否收费，转`unknown`并保留预占；禁止自动再次推理。晚到的已确认结果仍可幂等结算。
- `pending`按既有任务查询契约核对；已结算请求不会因重试改变账单。

新网关保留New API响应编号，供查询原请求及人工证据核对。未知结果不因超时自动认定免费；人工结算沿用带凭证的运营入口。到期/暂停下已受理任务已接入单请求恢复凭据，仅查询、轮询及确认，不恢复新调用；撤销后由官方人工核对。见[监控与恢复说明](ACCOUNTING_MONITORING.md)。

一级恢复任务每30秒按索引读取最多50条到期的官方请求及未确认事件。失败次数及指数退避排期持久化，重启不会清空；自接模型未知请求不自动重发。并发恢复通过同请求锁及唯一结算保证资金幂等，重复查询不触发再次推理。事件只有本地结算提交后才确认。

运营对账接口返回最多200条未知/过期记录、未确认事件及欠款钱包，同时返回总数，避免列表截断被误认无积压。尾差欠款继续阻止新请求，充值先抵扣。已实现飞书Webhook异常/恢复通知、持久重试及轮转资金巡检；生产容量和备份策略仍需验证。

## 验证与边界

独立数据库覆盖：并发余额不足、不同钱包独立提交、跨钱包命令冲突、充值凭证复用、不可变流水、事件插入故障整笔回滚、重复结算、重建服务、发送前/后崩溃状态恢复、尾差欠款、重试排期、大小写ID、旧账资金/预占/事件导入、旧二进制式直接SQL更新拒绝、异常迁入回滚、用户权益不变，以及独立服务实际启动/MFA认证/充值/余额接口。

执行`npm run check`及`npm run test:licensing:mysql`。测试脚本只创建自身临时容器和独立数据库，默认模拟供应商，无付费调用；相同领域已在测试服务器独立MySQL 5.7数据库验证。详细本轮版本和结果见进度表。

本轮：后台153项通过；独立MySQL 8.4.10和5.7.44领域集成通过。8.4.10脚本还在自身容器内备份并恢复到新库，对比所有账本摘要、原生预占和用户积分数据，验证恢复后去重结算及触发器仍有效；随后验证20钱包、1000请求、40并发工作单元、两个连接池的余额/预占/事件守恒。临时容器及其匿名数据卷结束后删除。5.7.44使用新建独立测试库，结束后只删除该次两个库，没有覆盖现有验收服务数据。

拆表、隔离恢复和并发基线不等于生产规模/长周期验收。正式切换前仍需按实际部署做容量、索引及备份策略/RPO/RTO演练、外部存活监控、真实历史一级迁入和7天试点。授权中心聚合存储、多进程授权缓存及未适配业务仍按总规划推进。
