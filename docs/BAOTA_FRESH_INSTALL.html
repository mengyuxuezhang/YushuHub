YUSHUHUB · 代理操作简版

在宝塔全新安装管理后台

导入预制编排 → 启动 → 设置域名和 HTTPS → 页面初始化 → 登录接入授权

候选版本 1.9.69-baota.1 · 待独立功能验收，尚未正式发布。本文用于全新空实例；已有经营数据请走独立迁移路线。

1 · 准备三样东西

  • 发行方提供的固定版本 compose.yaml；镜像地址应包含 @sha256:。不要自行替换成 latest。
  • 自己专用的安装口令：32–128 个无空格字符，建议用密码管理器生成；它与管理员密码不同，不发到群聊。
  • 后台最终域名及其 HTTPS 证书配置权限。经营功能还需要授权方签发的完整接入信息。

服务器使用 Linux amd64，已安装可用的 Docker Engine 与 Compose 插件。预留至少 2GiB 可用内存、镜像与备份磁盘空间；已有其他站点时让维护者确认资源。模板默认业务 512MiB、数据库 768MiB，实际负载可能需维护者调整。

不需要在宝塔再装一套数据库，也不需要 Node/npm 编译。专用 MySQL 与后台一同启动，其数据库端口不会开放到公网。

2 · 导入并启动

  1. 进入Docker → 容器编排，选择创建编排，将发行方的 YAML 内容粘贴进去；支持文件创建的版本也可选择文件。[1][2]
  2. 给项目起固定名称，例如 yushuhub-admin。以后保留此名称，否则会产生另一套卷。
  3. 找到 YUSHUHUB_INSTALL_TOKEN，将该行占位文字替换成你刚生成的安装口令。不要把真实口令粘贴到共享文档。未替换模板时安装应失败。
  4. 默认本机端口 7077。如已占用，只调整 127.0.0.1:7077:7077 中间那段宿主端口，并相应调整后面的反代目标。
  5. 保存并启动。容器列表应出现 prepare、database、admin；prepare 正常完成后显示已退出，这是预期。database 随后就绪，admin 显示存活。

“Docker→网站”空白不代表容器没启动。请到“容器编排/容器”查看，不另建第二份项目。后台等待页面初始化时，存活健康不等于已经能经营。

3 · 绑定域名、启用 HTTPS

  1. 在宝塔原宿主网站入口创建或选择此后台域名站点；DNS 指向该服务器。
  2. 设置反向代理目标为 http://127.0.0.1:7077（如修改了宿主端口则对应替换），发送 Host 保留原域名。[3]
  3. 启用该域名 SSL，并让 HTTP 跳转 HTTPS。配置生效后打开最终 HTTPS 地址，应看到“设置你的管理后台”。

反代需传递 Host、X-Real-IP、X-Forwarded-For、X-Forwarded-Proto $scheme，保留业务需要的 WebSocket/长连接。上传限制与读取超时按实际业务设置；不要重复添加相互冲突的 location。配置检查通过后仅平滑重载原 Nginx。

这条简版路线要求 Nginx 在宿主。若使用 Docker bridge Nginx，它的 127.0.0.1 是自己，不能原样填写这个目标；交维护者适配，不把数据库或后台改为公网监听。

4 · 页面初始化与首次登录

  1. 填写安装口令、最终 HTTPS 域名和管理员密码。管理员密码为 16–128 位，包含字母与其他字符；账号固定 admin。
  2. 点击“初始化后台”，等待数据库建表和默认数据准备。通常一至三分钟，页面就绪后自动转到登录页。
  3. 使用 admin 和刚设置的密码，按正常验证码流程登录。
  4. 进入授权接入页面，粘贴授权方提供的完整接入信息，按页面提示激活并应用。部署域名必须与授权绑定一致。

没有默认通用管理员密码。安装口令不会出现在初始化页面或普通日志里；完成后安装接口关闭，重启不会再次要求设置或重置管理员。尚无有效中心授权时可查看和处理授权状态，经营操作仍被禁止；不要切换 legacy 来绕过授权。

中断或失败时先查看本项目日志，保留卷；再次出现初始化页时，用首次提交的域名和管理员密码重试。数据库和初始化记录不匹配时停止交维护者，不清空数据库。

5 · 日常观察、重启与备份

观察项预期与处理
prepare正常结束，退出码0；重复运行保留已有随机凭据，不重置数据库。
database / admin数据库健康后业务启动；等待初始化时 healthz 存活，readyz 仍未就绪。登录及授权状态另行检查。
重启保留项目名和全部卷，先确保数据库可用再启动业务。unless-stopped 不会替你恢复手工停止的容器。
日志在容器列表查看本项目日志，分享前脱敏。默认每容器日志10MiB×3，应用文件日志另行保留。

必须成套备份：数据库一致性 dump、mysql-data、root-secret、app-secret、app-data（含初始化记录、加密密钥及授权状态）、published、日志保留策略，以及原 YAML、域名和SSL配置。数据库运行中直接复制卷不能代替一致性备份；维护者应在隔离环境演练恢复。

备份应存于 Web 根目录之外的受控位置。恢复全套到同一实例身份和原项目名，不能只拿数据库配一套新密钥；不要把旧库覆盖当前库作为普通重启步骤。

6 · 后续升级与当前交付范围

本阶段已实现新装、初始化、登录及持久化。独立宿主受控升级服务的新装登记适配仍在开发，当前候选不宣称后台一键升级已可用；未绑定服务时，应看到明确的未绑定提示。

升级服务应由维护者进行一次可信安装；业务容器不会获得 root 控制器或 Docker socket。普通代理不需要走旧 PM2 的登记/迁移 review 长链。待后续固定候选补齐后，再按发行单使用签名版本、备份、任务收据和恢复入口。

不要通过面板拉 latest、编辑镜像、删卷或重建项目代替受控升级。安装成功也不表示生产发行已获批准。
